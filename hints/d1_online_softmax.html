D1 · Online softmax、(O, LSE) 状态与 split-KV 合并

FlashAttention 1 到 4 都建立在同一个递推上：softmax 不必等看完整行。维护“目前的最大值、指数和、未归一化的输出”，每来一块 key 就乘一个修正因子。同一个代数还告诉你两段 attention 的结果怎么合并——split-KV decode 和 FA 的 combine kernel 都靠它。

题面速览

  • 在系统中的位置：FA2 的 Softmax::softmax_rescale_o（每块更新 row_max、row_sum，并把 acc_o 乘 exp2(old_max − new_max)）；全被遮住的行用 max_scaled = max == -INF ? 0 : max（softmax.h L76）。合并：SGLang 的 merge_state.py、FA 的 flash_fwd_combine.py。G3 在 5090 上把这套递推写进寄存器 fragment。
  • 你要实现：online_softmax_stats、online_attention、merge_states、split_kv_attention。
  • 难点在这几条规则：
    1. 新最大值出现时，旧的 l 和 acc 都要乘 exp(m_old − m_new)。
    2. 一行到目前为止全被遮住（m = −inf）时，−inf − (−inf) = NaN：用 0 做基准。
    3. 合并：lse = logaddexp(lse_a, lse_b)，权重 exp(lse_i − lse)，两段都空时得 (0, −inf)。
    4. split-KV 允许空段（段数 > key 数）。

验收要点：分块统计 = 直接计算（多种块大小）· 空 / 全 −inf · 大数不溢出 · 分块 attention = 参考（块大小 1..64）· 全遮住的行 0 / −inf 且无 NaN · 两半合并 = 全量 · 和空段合并不变 · split-KV（1..50 段）= 参考 · 部分段全被遮住的 split-KV。

直觉与类比

类比 · 换汇率的记账

你在记一笔外币账：每笔收入都按“当前最高汇率”换算成本币记下来。突然来了一笔汇率更高的钱，你的基准变了——之前记的所有金额都要按新旧汇率之比（exp(m_old − m_new)）折算一下。online softmax 就是这样：m 是基准汇率，l 是折算后的总额，acc 是折算后的加权和。两本分别记的账要合并时，各自带着“总额的对数”（LSE），按 exp(lse_i − lse) 的比例加权就行——这就是 split-KV 的 merge。

逐步演示

▶ 一行分数 [1, 3, 2, 6, 0, 5]，块大小 2
1. 第一块

m 从 −inf 变成 3，α = exp(−inf) = 0（旧状态为空），l = e⁻² + e⁰ = 1.1353。

2. 新的最大值

6 > 3：α = exp(3 − 6) = 0.0498。l = 1.1353 · 0.0498 + e⁻⁴ + e⁰ = 1.0748。acc 也乘同一个 α。

3. 最大值不变

α = 1，直接累加：l = 1.0748 + e⁻⁶ + e⁻¹ = 1.4452，和一次性计算 Σexp(x − 6) 完全一样。

4. 合并两段

一个 query、4 个 key 分两段算：前一段 (o, lse) = (1.731, 2.313)，后一段 (3.953, 3.049)；merge_states → (3.233, 3.440)，和一次算全部 4 个 key 的结果一致。

易错点

  • 只修正 l 不修正 acc。 输出会偏向前面的块。
  • exp(−inf − (−inf))。 全被遮住的行（causal 的左上角、padding、split-KV 的空段）会产生 NaN 并在合并时传染给整行（test_fully_masked_rows_give_zero_and_neg_inf）。
  • 合并用 exp(lse_a) 直接加。 lse 可能是 80、100，exp 溢出；要减去合并后的 lse 再取 exp。
  • 合并时 −inf 一侧的权重算成 NaN。 exp(−inf − (−inf))，同样的坑，要显式判断。
  • O 没归一化就合并。 本题约定每段的 O 已经归一化，合并公式是加权平均；如果存的是未归一化的 acc，公式不同。

关键问题

  1. 为什么 α 要同时乘到 l 和 acc 上？
  2. 合并两段时，为什么只需要 lse，不需要分别的 m 和 l？
  3. 为什么 decode 要 split-KV，prefill 一般不用？
  4. FA2 为什么在 log2 域里算？
L2思路与常见坑拆解与常见坑（中度剧透）
  • 状态：m = full(nq, -inf)、l = zeros(nq)、acc = zeros((nq, dv))。
  • 每块：S（加 mask）、m_new = maximum(m, S.max(1, initial=-inf))、safe = where(isfinite(m_new), m_new, 0)、alpha = exp(where(isfinite(m), m - safe, -inf))、P = exp(S - safe)。
  • 结束：ok = l > 0；O 和 lse 对 ok 的行正常算，其余 0 / −inf。
  • merge_states：np.logaddexp；每边权重对 −inf 显式置 0。
L3详解：答案几乎是答案（重度剧透）
关键问题答案
  1. O = acc / l，两者都是“以 m 为基准”的量；基准换了，分子分母要同时换，比值才不变。
  2. 一段的贡献可以写成 exp(lse_i) · O_i（O_i 已归一化，exp(lse_i) 就是这段的 Σexp）。合并 = 按 exp(lse_i) 加权平均，lse 一个数就够。反向传播也只存 lse（FA2 的 softmax_lse）。
  3. decode 时 query 只有 1 个 token：按 (batch, head, query 块) 并行的 CTA 数太少，喂不饱 SM；切开 key 让多个 CTA 各算一段再合并（FlashDecoding）。prefill 的 query 块已经够多。
  4. GPU 的特殊函数单元只有 ex2（2 的幂），exp(x) 本来就要先乘 log2 e。把 scale · log2 e 合进分数的缩放里，省掉每个元素一次乘法（FA2 softmax_scale_log2）。D3 的 FA4 更进一步，把部分 ex2 挪到 FMA 上。

"""D1 · Online softmax, (O, LSE) states and merging split-KV partials — reference solution.

FlashAttention 的全部魔法都建立在一个递推上：softmax 不必等看完整行再算。维护“到目前为止的
最大值 m、指数和 l、未归一化的输出 acc”，每来一块新的 key 就把旧的 l、acc 乘 exp(m_old − m_new)
修正一下。同一个代数还给出“两段 attention 结果怎么合并”：每段带上 log-sum-exp（LSE），
合并就是按 exp(lse_i − lse) 加权。split-KV decode（FlashDecoding、FlashInfer 的 merge_state）
和 FA3/FA4 的 combine kernel 都是这么做的。

约定：自然对数；softmax_scale 由调用者给出；mask 为 bool 数组（True = 保留）。被完全遮住的行
（没有任何保留的 key）输出全 0、lse = −inf，而且不能产生 NaN。

- online_softmax_stats(x, block)：1D x 按 block 个一组顺序处理，返回 (m, l)，m = max(x)，
  l = Σ exp(x − m)。x 为空或全为 −inf 时返回 (−inf, 0.0)。
- online_attention(Q, K, V, scale, block, mask=None)：Q (nq, d)、K (nk, d)、V (nk, dv)。对 key 按 block 分块，
  用 m / l / acc 递推，返回 (O (nq, dv), lse (nq,))，O = softmax(scale·QKᵀ 遮罩后) V，lse = log Σ exp(...)。
- merge_states(o_a, lse_a, o_b, lse_b)：逐行合并两段结果，返回 (o, lse)；两边都是 −inf 的行得 (0, −inf)。
- split_kv_attention(Q, K, V, scale, num_splits, mask=None)：key 用 np.array_split 切成 num_splits 段
  （段可以为空），每段 online_attention（block 取该段长度，至少 1），再从左到右依次 merge_states。

API
    online_softmax_stats(x, block) -> tuple[float, float]
    online_attention(Q, K, V, scale, block, mask=None) -> tuple[np.ndarray, np.ndarray]
    merge_states(o_a, lse_a, o_b, lse_b) -> tuple[np.ndarray, np.ndarray]
    split_kv_attention(Q, K, V, scale, num_splits, mask=None) -> tuple[np.ndarray, np.ndarray]
"""
from __future__ import annotations

import numpy as np


def online_softmax_stats(x, block: int) -> tuple[float, float]:
    """分块扫描一遍，得到最大值和指数和。"""
    m, l = -np.inf, 0.0
    x = np.asarray(x, dtype=np.float64)
    for i in range(0, len(x), block):
        blk = x[i:i + block]
        m_new = max(m, blk.max(initial=-np.inf))
        if m_new == -np.inf:
            continue            # 这块全是 −inf：什么都不变（否则 exp(−inf − (−inf)) = NaN）
        # 旧的和要换到新的基准：Σ exp(x − m_old) · exp(m_old − m_new)。
        l = l * np.exp(m - m_new) + np.exp(blk - m_new).sum()
        m = m_new
    return m, l


def online_attention(Q, K, V, scale: float, block: int, mask=None):
    """FA 的核心递推：按 key 块更新 m、l、acc；最后 O = acc / l。"""
    Q, K, V = (np.asarray(a, dtype=np.float64) for a in (Q, K, V))
    nq, nk = Q.shape[0], K.shape[0]
    m = np.full(nq, -np.inf)
    l = np.zeros(nq)
    acc = np.zeros((nq, V.shape[1]))
    for j in range(0, nk, block):
        S = scale * Q @ K[j:j + block].T
        if mask is not None:
            S = np.where(mask[:, j:j + block], S, -np.inf)
        m_new = np.maximum(m, S.max(axis=1, initial=-np.inf))
        # m_new 仍是 −inf 的行（到目前为止全被遮住）用 0 做基准，避免 −inf − (−inf)。
        # FA2 源码里叫 “max_scaled = max == -INF ? 0 : max”（softmax.h），同一个技巧。
        safe = np.where(np.isfinite(m_new), m_new, 0.0)
        alpha = np.exp(np.where(np.isfinite(m), m - safe, -np.inf))
        P = np.exp(S - safe[:, None])
        l = l * alpha + P.sum(axis=1)
        acc = acc * alpha[:, None] + P @ V[j:j + block]
        m = m_new
    ok = l > 0
    O = np.where(ok[:, None], acc / np.where(ok, l, 1.0)[:, None], 0.0)
    lse = np.where(ok, m + np.log(np.where(ok, l, 1.0)), -np.inf)
    # 为什么返回 lse 而不是 (m, l)：lse 一个数就够合并（见 merge_states），反向传播也只要它
    # （FA2 的 softmax_lse）。O 已经归一化，所以每段的结果本身就是“这段 key 上的 attention”。
    return O, lse


def merge_states(o_a, lse_a, o_b, lse_b):
    """两段 (O, LSE) 合并成一段。"""
    o_a, o_b = np.asarray(o_a, dtype=np.float64), np.asarray(o_b, dtype=np.float64)
    lse_a, lse_b = np.asarray(lse_a, dtype=np.float64), np.asarray(lse_b, dtype=np.float64)
    lse = np.logaddexp(lse_a, lse_b)            # −inf 与 −inf 合并仍是 −inf，不会出 NaN
    fin = np.isfinite(lse)
    base = np.where(fin, lse, 0.0)
    wa = np.where(np.isfinite(lse_a), np.exp(lse_a - base), 0.0)
    wb = np.where(np.isfinite(lse_b), np.exp(lse_b - base), 0.0)
    # 权重 wa + wb = 1：每段的 O 是那段 key 上的加权平均，合起来就是按“质量”exp(lse) 再平均一次。
    o = wa[:, None] * o_a + wb[:, None] * o_b
    return np.where(fin[:, None], o, 0.0), lse


def split_kv_attention(Q, K, V, scale: float, num_splits: int, mask=None):
    """把 key 切成 num_splits 段分别算，再依次合并。"""
    idx = np.array_split(np.arange(K.shape[0]), num_splits)
    o = lse = None
    for part in idx:
        sub_mask = None if mask is None else mask[:, part]
        o_p, lse_p = online_attention(Q, K[part], V[part], scale, max(len(part), 1), sub_mask)
        if o is None:
            o, lse = o_p, lse_p
        else:
            o, lse = merge_states(o, lse, o_p, lse_p)
    # decode 时 nq 很小（1 个 token × head 数），只按 query 并行喂不饱 132 个 SM；
    # 切开 key 让多个 CTA 各算一段，再用一个小 kernel 合并——这就是 FlashDecoding。
    return o, lse

面试官追问 & 对照源码

  • “FA 的反向为什么只存 lse 就够？” 反向要重算 P = exp(S − lse)：有了 lse，不需要 m 和 l。
  • “cascade attention / 共享前缀怎么用 merge？” 共享前缀的 KV 算一次（对所有请求），各请求的私有后缀各算一次，再按 lse 合并——FlashInfer 的 cascade、SGLang 的 cascade.cu。
  • “merge 能用 BF16 存 O 吗？” O 用 BF16 存问题不大；lse 必须 FP32，否则权重误差直接放大到输出。
  • “为什么 split 的段数不能太多？” 每段都要写一份 (O, lse) 到 HBM 再读回来合并，段数 × head_dim 的额外流量；FA3 / FlashInfer 用启发式按 SM 数和序列长度选段数。
