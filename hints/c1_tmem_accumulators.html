C1 · Blackwell TMEM：列分配、双缓冲累加器与 2-CTA MMA

B200 每 SM 每时钟 8192 FLOP，128×256 的 FP32 累加器已经占半个寄存器堆。Blackwell 的回答是 Tensor Memory：每 SM 256 KB 专门放累加器，像 malloc 一样按列申请；512 列正好放下两个累加器，于是 MMA 和 epilogue 天然重叠。

题面速览

  • 在系统中的位置：TMEM 分配器 Allocator1Sm（tcgen05.alloc，2 的幂、32..512 列，一个 warp 发起）；累加器流水 PipelineUmmaAsync，在 kernel 里叫 AccumulatorPipeline（AccumulatorPipelineStageCount）；2-CTA MMA 是 SM100_MMA_F16BF16_2x1SM_SS（tcgen05.mma.cta_group::2）。真跑需要 B200 / GB200（sm100a）；RTX 5090（sm120）没有 TMEM 和 tcgen05。
  • 你要实现：TmemAllocator（alloc / free / used）、acc_columns、max_acc_buffers、acc_pipeline、per_sm_intensity。
  • 难点在这几条规则：
    1. TMEM = 128 lane × 512 列 × 32 bit；累加器的 M 对应 lane、N 对应列：128×256 FP32 = 256 列。
    2. 分配是 2 的幂、≥ 32 列；本题用“按大小对齐的 first-fit”作为放置模型，失败返回 None 且不改状态。
    3. MMA warp 写累加器 i % buffers 之前，要等 tile i − buffers 的 epilogue 读完它。
    4. 2-CTA：两个 SM 合算 256×N，每个 SM 只装一半 B，每 SM 强度从 85 升到 128。

验收要点：两个 256 列塞满 · 对齐的 first-fit · 释放后复用 · 非法大小 · 非法释放 · 失败不改状态 · Rubin 576 列 · 列数与缓冲数 · 单缓冲串行 · 双缓冲重叠 · 缓冲越多不越慢 · 2-CTA 强度。

直觉与类比

类比 · 两个托盘的流水线

厨师（MMA warp，只有一个线程发指令）把菜炒进托盘（TMEM 里的累加器），服务员（epilogue warp）把托盘上的菜装盘送走（TMEM → 寄存器 → SMEM → TMA store）。只有一个托盘时，厨师炒完得等服务员送完才能炒下一锅。TMEM 有 512 列，一个 128×256 的托盘占 256 列——正好两个托盘：厨师炒第二锅的时候服务员在送第一锅。这就是 Hopper 要靠 pingpong（把锅切小、两个厨师轮流）才能做到的事，Blackwell 用“多一个托盘”就做到了，而且锅不用变小。

逐步演示

▶ 4 个 tile，ML = 10，EP = 6
1. 单缓冲

tile 1 的 MMA 必须等 tile 0 的 epilogue（16）结束：每个 tile 10 + 6，4 个 = acc_pipeline(4, 10, 6, 1) = 64。8 个 tile = 128。

2. 双缓冲

tile 1 写累加器 1，不用等；tile 2 写累加器 0，要等 tile 0 的 epilogue（16），它早在 MMA 跑到 20 之前就结束了：总时间 46。8 个 tile = 86（稳态每 tile 10）。

3. epilogue 比 MMA 长

EP = 15：epilogue 只有一组 warp、串行处理，总时间 = 10 + 4·15 = 70。这时该加 epilogue warp，或者把 epilogue 切成子 tile（CUTLASS 的 NumEpilogueSubTiles）。

4. 2-CTA

per_sm_intensity(128, 256) = 85.3；per_sm_intensity(256, 256, cta_pair=True) = 128。B200 要 64（A1），2-CTA 给了一倍的余量。

易错点

  • alloc 失败时已经标记了一部分列。 test_failed_alloc_changes_nothing。
  • 对齐忘了。 32..63 空着也不能放 64 列的块（本题的放置模型），test_alignment_first_fit。
  • free 不校验。 释放一个从没分配过的区间、或重复释放，都应报错。
  • 双缓冲时 MMA 等错了 tile。 要等的是 i − buffers 的 epilogue，不是 i − 1。
  • epilogue 并行处理多个 tile。 本题只有一组 epilogue warp，必须按顺序做（max(ml_end[i], ep_end[i-1])）。

关键问题

  1. 128×256 的 FP32 累加器为什么占 256 列而不是 128？
  2. 双缓冲的稳态周期是多少？
  3. 一个 SM 上同时跑两个 CTA，各要两个 256 列的累加器，会发生什么？
  4. 2-CTA MMA 为什么能省一半的 B？
L2思路与常见坑拆解与常见坑（中度剧透）
  • 分配器：一个长度 capacity 的布尔数组 + 已分配集合 {(start, ncols)}；alloc 从 0 开始按步长 ncols 扫描。
  • acc_pipeline：两个列表 ml_end、ep_end；s = max(ml_end[-1], ep_end[i-buffers])；es = max(ml_end[i], ep_end[-1])。
  • per_sm_intensity：pair 时 m = tile_m / 2，强度 m·n / (m + n/2)。
L3详解：答案几乎是答案（重度剧透）
关键问题答案
  1. 128 行对应 128 个 lane（每 lane 一行），每行 256 个 FP32，每列 32 bit：256 列。
  2. max(ML, EP)：MMA 每 ML 出一个累加器，epilogue 每 EP 消耗一个。
  3. 第二个 CTA 分不到（512 列已满），tcgen05.alloc 会等；如果第一个 CTA 不及时 relinquish_alloc_permit / 释放，就成了串行。所以 CUTLASS 的 persistent kernel 每 SM 只跑一个 CTA，用 tile 调度器循环取 tile（C3）。
  4. MMA 读的 B 是两个 SM 的 SMEM 拼起来的：每个 SM 装 N/2 列，硬件通过 cluster 内的 DSMEM 把对方那一半也喂进 Tensor Core。A 各自装自己的 128 行。

"""C1 · Blackwell TMEM: column allocation, double-buffered accumulators and 2-CTA MMA — reference solution.

B200 每个 SM 每时钟 8192 FLOP：128×256 的 FP32 累加器已经占了半个寄存器堆，寄存器再也装不下。
Blackwell 的回答是 Tensor Memory（TMEM）：每个 SM 256 KB = 128 行（lane）× 512 列 × 32 bit，
专门放累加器。`tcgen05.mma` 由一个线程发起、把结果写进 TMEM；epilogue warp 再用 `tcgen05.ld`
读出来。TMEM 要像 malloc 一样按“列”申请（`tcgen05.alloc`，2 的幂、32..512 列），
而 512 列刚好放下两个 128×256 的累加器——MMA warp 写一个、epilogue warp 读另一个。

- TmemAllocator(capacity=512)：
  - alloc(ncols) -> int | None：ncols 必须是 [32, capacity] 内 2 的幂，否则 ValueError。
    本题的放置规则（简化模型）：从低到高找第一个“起点是 ncols 的倍数、且 [起点, 起点+ncols) 全空”的位置，
    返回起始列；没有返回 None。
  - free(start, ncols)：必须恰好对应一次尚未释放的 alloc，否则 ValueError。
  - used：已分配列数。
- acc_columns(tile_n, acc_bits=32)：一个（每 CTA）M = 64 或 128 行的累加器占多少列 = tile_n·acc_bits / 32
  （每个 lane 一行；M = 64 也按 tile_n 列占，只是只用一半 lane）。
- max_acc_buffers(tile_n, capacity=512, acc_bits=32)：最多放几个累加器 = capacity // acc_columns。
- acc_pipeline(n_tiles, ML, EP, buffers) -> float：MMA warp 依次算 tile 0..n−1，tile i 写累加器 i % buffers；
  tile i 的 mainloop 开始 = max(tile i−1 的 mainloop 结束, tile i−buffers 的 epilogue 结束)；
  epilogue 只有一组 warp，按顺序做：tile i 的 epilogue 开始 = max(tile i 的 mainloop 结束,
  tile i−1 的 epilogue 结束)，花 EP。返回最后一个 epilogue 的结束时刻（n_tiles = 0 时为 0）。
  buffers < 1 抛 ValueError。
- per_sm_intensity(tile_m, tile_n, cta_pair=False)：每个 SM 每步 k 的 FLOP / SMEM 字节（BF16）。
  单 CTA：tile_m·tile_n / (tile_m + tile_n)。cta_pair=True 时 tile_m×tile_n 是两个 SM 合作的 tile：
  每个 SM 算 tile_m/2 行、只装一半的 B（tile_n/2 列），强度 = (tile_m/2)·tile_n / (tile_m/2 + tile_n/2)。

API
    TmemAllocator(capacity=512)  .alloc(ncols) -> int | None  .free(start, ncols)  .used
    acc_columns(tile_n, acc_bits=32) -> int
    max_acc_buffers(tile_n, capacity=512, acc_bits=32) -> int
    acc_pipeline(n_tiles, ML, EP, buffers) -> float
    per_sm_intensity(tile_m, tile_n, cta_pair=False) -> float
"""
from __future__ import annotations


class TmemAllocator:
    def __init__(self, capacity: int = 512):
        """capacity 列的 TMEM（B200 是 512；CUTLASS 里 Rubin / Sm107 是 576）。"""
        self.capacity = capacity
        self._busy = [False] * capacity
        self._allocs: set[tuple[int, int]] = set()

    def alloc(self, ncols: int):
        """申请 ncols 列；放不下返回 None。"""
        if ncols < 32 or ncols > self.capacity or ncols & (ncols - 1):
            raise ValueError("TMEM allocations are a power of two in [32, capacity] columns")
        # 按大小对齐的 first-fit 是本题的简化；真实硬件的放置策略没有公开。
        # 关键事实是：分配粒度是 32 列，整块连续；一个 SM 上的多个 CTA 共享这 512 列，
        # 所以 CUTLASS 在 kernel 开头分配、结尾释放，并用 relinquish_alloc_permit 让后来的 CTA 能分到。
        for start in range(0, self.capacity - ncols + 1, ncols):
            if not any(self._busy[start:start + ncols]):
                for c in range(start, start + ncols):
                    self._busy[c] = True
                self._allocs.add((start, ncols))
                return start
        return None

    def free(self, start: int, ncols: int) -> None:
        """释放一次分配。"""
        if (start, ncols) not in self._allocs:
            raise ValueError("free does not match an allocation")
        self._allocs.remove((start, ncols))
        for c in range(start, start + ncols):
            self._busy[c] = False

    @property
    def used(self) -> int:
        return sum(self._busy)


def acc_columns(tile_n: int, acc_bits: int = 32) -> int:
    """累加器占的 TMEM 列数。"""
    # TMEM 的“行”就是 lane（128 个），对应累加器的 M；“列”对应 N。所以 M=128 的 tile 正好一行一个 lane，
    # N=256 的 FP32 累加器占 256 列。
    return tile_n * acc_bits // 32


def max_acc_buffers(tile_n: int, capacity: int = 512, acc_bits: int = 32) -> int:
    """TMEM 里最多能放几个这样的累加器。"""
    return capacity // acc_columns(tile_n, acc_bits)


def acc_pipeline(n_tiles: int, ML: float, EP: float, buffers: int) -> float:
    """MMA warp 和 epilogue warp 通过 buffers 个 TMEM 累加器流水。"""
    if buffers < 1:
        raise ValueError("need at least one accumulator buffer")
    ml_end: list[float] = []
    ep_end: list[float] = []
    for i in range(n_tiles):
        # MMA 要写的累加器必须已经被 epilogue 读空了：这就是 CUTLASS 的 accumulator pipeline
        # （PipelineUmmaAsync）里 MMA warp 等 “acc empty”、epilogue 等 “acc full”。
        s = max(ml_end[-1] if ml_end else 0.0, ep_end[i - buffers] if i >= buffers else 0.0)
        ml_end.append(s + ML)
        es = max(ml_end[i], ep_end[-1] if ep_end else 0.0)
        ep_end.append(es + EP)
    # 一个累加器：每个 tile 都是 ML + EP 串行（Hopper cooperative 的老问题）；
    # 两个累加器：稳态周期变成 max(ML, EP)，而且不像 Hopper pingpong 那样要把 tile 切小。
    return ep_end[-1] if ep_end else 0.0


def per_sm_intensity(tile_m: int, tile_n: int, cta_pair: bool = False) -> float:
    """每 SM 每步 k 的 FLOP / SMEM 字节（BF16）。"""
    if cta_pair:
        # cta_group::2：两个 SM 合算一个 256×N 的 tile，每个 SM 装自己的 128 行 A 和一半 B，
        # 但 MMA 读的是两个 SM 的 B 拼起来的整块。每个 SM 的 SMEM 流量少了一半的 B。
        m = tile_m / 2
        return m * tile_n / (m + tile_n / 2)
    return tile_m * tile_n / (tile_m + tile_n)

面试官追问 & 对照源码

  • “从 Hopper kernel 迁到 Blackwell 要改什么？” MMA 发起方从 “consumer warpgroup 的 128 个线程执行 wgmma” 变成 “一个 MMA warp 里 elect 一个线程执行 tcgen05.mma”；累加器从寄存器 fragment 变成 TMEM tensor（开头 alloc、结尾 free）；完成通知从 wgmma.wait_group 变成 tcgen05.commit 到 mbarrier；epilogue 先 tcgen05.ld 把 TMEM 读进寄存器。
  • “FA4 把什么放进了 TMEM？” S、P 和 O 都在 TMEM：QKᵀ 写 S 到 TMEM，softmax warp 读 S、写 P（BF16，覆盖在 S 的位置），PV 的 A 操作数直接从 TMEM 读，O 也在 TMEM，rescale 由 correction warp 做（D3）。见 flash_fwd_sm100.py。
  • “DeepGEMM 的 scale factor 也进 TMEM 吗？” 是：block-scaled MMA 的 scale 用 tcgen05.cp（UTCCP）从 SMEM 拷进 TMEM，MMA 指令描述符里带 scale 的 TMEM 地址，见 sm100_fp8_fp4_gemm_1d1d.cuh（C2 讲 block scaling）。
  • “Rubin 有什么不同？” CUTLASS 里 Sm107 的 TMEM 是 576 列，exclusive 分配可以是任意 32 的倍数（见 Allocator1Sm 的注释）。
