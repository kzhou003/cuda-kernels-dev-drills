A2 · mma.sync m16n8k16 的 fragment 布局与 ldmatrix

从 Volta 起矩阵乘是一条 warp 指令，但 32 个线程各自只拿着矩阵的几个元素。写 Ampere 风格 kernel 的核心，就是让每个线程寄存器里放的恰好是 mma 要的那几个——ldmatrix 让这件事只要一条指令。

文件: mine/a2_mma_fragments.py 你的代码 · tests/test_a2_mma_fragments.py 测试 · solutions/a2_mma_fragments.py 参考解

题面速览

  • 在系统中的位置：CuTe 把一条 PTX mma 包成一个 “MMA atom”，例如 SM80_16x8x16_F32BF16BF16F32_TN（A 4 个寄存器、B 2 个、C 4 个），线程到元素的映射写在 mma_traits_sm80.hpp 的 ALayout / BLayout / CLayout 里。ldmatrix 是 SM75_U32x4_LDSM_N（Turing 引入）。RTX 5090 上 G1、G3 用的就是这两条指令。
  • 你要实现：a_coords / b_coords / c_coords（每个 lane 持有哪些元素）、mma_m16n8k16（warp 级 MMA 的语义）、ldmatrix（谁给地址、谁拿数据）、a_tile_row_addrs / b_tile_row_addrs（让 ldmatrix 直接读出 fragment 布局的地址）。
  • 难点在这几条规则：
    1. g = lane / 4（行组）、t = lane % 4（组内序号）；一个 quad（4 个相邻 lane）共同拥有两整行（g 和 g+8）。
    2. 每个 32-bit 寄存器装两个相邻元素：A、C 是同一行相邻两列；B 是同一列相邻两个 k。
    3. A 的寄存器顺序是 左上、左下、右上、右下 四个 8×8 子块。
    4. ldmatrix：lane 8j..8j+7 给出第 j 个 8×8 矩阵的 8 行地址；lane l 拿到每个矩阵第 l/4 行的第 2(l%4)、+1 列。

验收要点：lane 0 / 5 的坐标 · 每个元素恰好属于一个 lane · warp MMA = numpy 矩阵乘 · C 布局和 A 布局按行对齐 · ldmatrix.x1 的分发 · num 非法 · x4 + A 地址 = A fragment（多种 ld）· x2 + B 地址 = B fragment · 从“SMEM”到 MMA 的完整链路。

直觉与类比

类比 · 32 个人一起拼一幅 16×16 的拼图

一个 warp 是 32 个人围着桌子拼图。规则是：每 4 个人一组（quad），第 g 组负责第 g 行和第 g+8 行；组里第 t 个人负责这两行的第 2t、2t+1 列和第 2t+8、2t+9 列——每次两块相邻的拼一起放进一个口袋（寄存器）。ldmatrix 像是一个分拣员：32 个人各报一个“这一行在哪个抽屉里”的地址（8 个人报一个 8×8 小块的 8 行），分拣员把整块搬出来，再按“每 4 人一行、每人两块”的规则塞进各自口袋。报地址的人和拿到拼图的人，不是同一套对应关系——这是最容易绕晕的地方。

图解：A 的 4 个寄存器 = 4 个 8×8 子块

逐步演示

▶ lane 5 的一生：从 SMEM 到累加器
1. 坐标

lane 5：g = 1，t = 1。a_coords(5) = (1,2) (1,3) (9,2) (9,3) (1,10) (1,11) (9,10) (9,11)：行 1 和行 9，列 2–3 和 10–11。

2. 报地址

a_tile_row_addrs(0, 16)：lane 0..7 报矩阵 0（左上）的第 0..7 行 = 0, 16, …, 112；lane 8 报矩阵 1（左下）第 0 行 = 128；lane 16 报矩阵 2（右上）第 0 行 = 8；lane 24 报矩阵 3 第 0 行 = 136。lane 5 报的是 80（矩阵 0 第 5 行），但它拿到的不是第 5 行。

3. 拿数据

以 smem[i] = i 为例，ldmatrix.x4 后 lane 5 拿到 [18 19 146 147 26 27 154 155]：18 = 第 1 行第 2 列，146 = 第 9 行第 2 列，26 = 第 1 行第 10 列……正好是它的 a_coords。lane 0 拿到 [0 1 128 129 8 9 136 137]。

4. MMA

32 个 lane 的 a、b、c 拼成 16×16、16×8、16×8 三个矩阵，算 D = A·B + C，再按 c_coords 分回：lane 5 得到 D 的 (1,2) (1,3) (9,2) (9,3)。

易错点

  • 把 a1 和 a2 搞反。 PTX 规定 a1 是“下半”（行 g+8）而 a2 是“右半”（列 +8）。顺序错了 test_lane_zero_and_lane_five_coordinates 直接失败。
  • 以为 lane l 拿到的就是自己报地址的那一行。 分发规则是 l/4 行，和报地址的 l%8 无关；test_ldmatrix_x1_distributes_rows_to_quads 抓这个。
  • B 用了 A 的规律。 B 寄存器里的两个元素是同一列 n 的相邻两个 k（“col” 布局），所以 B 要按 N×K（B 的转置、k 连续）存放才能用非转置 ldmatrix；否则要 ldmatrix.trans（G3 读 V 时就是这样）。
  • x2 时用了 lane 16..31 的地址。 x2 只看 lane 0..15，其余地址被忽略（但必须是合法地址）。
  • 在 mma 里按 lane 顺序直接 reshape。 fragment 不是按 lane 连续排列的，必须按坐标拼。

关键问题

  1. 每个 lane 拿 A 的 8 个元素、B 的 4 个、C 的 4 个。总数对得上吗（16·16、16·8、16·8）？
  2. 一行 A（16 个元素）分布在哪几个 lane 上？
  3. 为什么 C 布局和 A 布局“按行对齐”很重要？
  4. B 如果是 K×N、n 连续地存在 SMEM 里，该用哪种 ldmatrix？
L2思路与常见坑拆解与常见坑（中度剧透）
  • 坐标函数：先算 g, t，A 按 (0,0),(8,0),(0,8),(8,8) 四个偏移各放两个相邻列。
  • mma_m16n8k16：建三个零矩阵，按坐标把 32 行数据散进去，D = A @ B + C，再按 c_coords 收回来。
  • ldmatrix：外层循环矩阵 j，取 8 行 smem[addr : addr+8]；内层循环 lane：r = l // 4，c = 2*(l % 4)。
  • 地址函数：A 的矩阵 j：行偏移 8*(j%2)，列偏移 8*(j//2)；B 的矩阵 j：列偏移 8*j（只有 2 个矩阵）。
L3详解：答案几乎是答案（重度剧透）
关键问题答案
  1. 32 × 8 = 256 = 16×16；32 × 4 = 128 = 16×8，两者都对得上，没有重复也没有遗漏（test_each_element_owned_by_exactly_one_lane）。
  2. 第 g 行在 lane 4g..4g+3 上，每个 lane 4 个元素（列 2t、2t+1、2t+8、2t+9）。所以 FA 里“求一行的最大值”只要在 quad 内做两次 __shfl_xor_sync（1 和 2）。
  3. S = QKᵀ 的输出在 C 布局，P = exp(S − m) 要作为下一次 P·V 的 A 操作数。两者行对齐，只需把 c0..c3 两两打包成 bf16（pack_bf16），零 shuffle。FA2 源码里的 convert_layout_acc_Aregs 做的就是这件事。
  4. ldmatrix.trans：它把 8×8 子块转置后再分发，lane 拿到的是同一列相邻两行，也就是 B 布局。G3 读 V（[key][d]）时用的就是 ldmatrix_x4_trans，对应 CuTe 的 SM75_U16x8_LDSM_T。

"""A2 · mma.sync m16n8k16 fragment layout and ldmatrix — reference solution.

从 Volta 开始，矩阵乘是“一个 warp 一条指令”：32 个线程各自拿着矩阵的几个元素（fragment），
一起执行 `mma.sync.aligned.m16n8k16.row.col.f32.bf16.bf16.f32`。写 Ampere 风格 kernel 的核心难点，
就是让每个线程寄存器里放的恰好是指令要的那几个元素。这道题用 numpy 把 PTX 文档里的布局写出来，
并模拟 `ldmatrix` 怎么一条指令把 SMEM 里的 tile 直接读成这个布局。

记号：lane ∈ [0, 32)，g = lane // 4（groupID），t = lane % 4（threadID_in_group）。

- a_coords(lane): A（16×16，row-major 语义）的 8 个元素，按寄存器顺序 a0..a3、每个寄存器低半在前：
    a0 = (g, 2t), (g, 2t+1)      a1 = (g+8, 2t), (g+8, 2t+1)
    a2 = (g, 2t+8), (g, 2t+9)    a3 = (g+8, 2t+8), (g+8, 2t+9)
  返回 8 个 (row, col)。
- b_coords(lane): B（16×8，K×N）的 4 个元素：b0 = (2t, g), (2t+1, g)；b1 = (2t+8, g), (2t+9, g)。返回 (k, n)。
- c_coords(lane): C/D（16×8 FP32）的 4 个元素：(g, 2t), (g, 2t+1), (g+8, 2t), (g+8, 2t+1)。返回 (m, n)。
- mma_m16n8k16(a, b, c): a 形状 (32, 8)、b (32, 4)、c (32, 4)，第 i 行是 lane i 按上面顺序持有的元素。
  返回 d (32, 4)：D = A @ B + C，按 c_coords 分回各 lane。用 float64 计算即可。
- ldmatrix(smem, row_addrs, num): 模拟 `ldmatrix.sync.aligned.m8n8.x{num}.shared.b16`（num ∈ {1,2,4}）。
  smem 是 1D 数组（元素 = b16），row_addrs 是 32 个元素偏移：第 j 个 8×8 矩阵的 8 行地址由
  lane 8j..8j+7 提供（num 之外的 lane 地址被忽略）。每行 8 个连续元素。
  结果 (32, 2·num)：lane l 的第 j 个寄存器（列 2j、2j+1）= 矩阵 j 的第 l//4 行、第 2·(l%4) 和 +1 列。
  num 不是 1/2/4 时抛 ValueError。
- a_tile_row_addrs(base, ld): 用 ldmatrix.x4 读一个从 base 开始、行跨度 ld 的 16×16 A tile 时，
  32 个 lane 各自该提供的行地址，使得结果恰好等于 a_coords 的布局。
- b_tile_row_addrs(base, ld): B 以 N×K（每行一个 n、k 连续，即 “TN” 里的 B^T）存放、从 base 开始、
  行跨度 ld 时，ldmatrix.x2 读一个 16(K)×8(N) 的 B tile 所需的地址（lane 0..15 有效，其余填 base 即可），
  使结果等于 b_coords 的布局。

API
    a_coords(lane) -> list[tuple[int, int]]
    b_coords(lane) -> list[tuple[int, int]]
    c_coords(lane) -> list[tuple[int, int]]
    mma_m16n8k16(a, b, c) -> np.ndarray
    ldmatrix(smem, row_addrs, num) -> np.ndarray
    a_tile_row_addrs(base, ld) -> list[int]
    b_tile_row_addrs(base, ld) -> list[int]
"""
from __future__ import annotations

import numpy as np


def a_coords(lane: int) -> list[tuple[int, int]]:
    """lane 持有的 8 个 A 元素坐标（寄存器 a0..a3，每个两个元素）。"""
    # 规律：行 = g 或 g+8（上下两半），列 = 2t 或 2t+8（左右两半），每个寄存器装两个相邻列。
    # 所以一个 quad（4 个相邻 lane，同一个 g）合起来正好覆盖第 g 行和第 g+8 行的全部 16 列。
    g, t = lane // 4, lane % 4
    out = []
    for r_off, c_off in ((0, 0), (8, 0), (0, 8), (8, 8)):     # a0, a1, a2, a3
        out += [(g + r_off, 2 * t + c_off), (g + r_off, 2 * t + c_off + 1)]
    return out


def b_coords(lane: int) -> list[tuple[int, int]]:
    """lane 持有的 4 个 B 元素坐标 (k, n)。"""
    # B 是“col”布局：一个寄存器里的两个元素是同一列 n、相邻两个 k。
    # 这正是 B^T（N×K、k 连续）按行存放时 ldmatrix 非转置读出来的样子。
    g, t = lane // 4, lane % 4
    return [(2 * t, g), (2 * t + 1, g), (2 * t + 8, g), (2 * t + 9, g)]


def c_coords(lane: int) -> list[tuple[int, int]]:
    """lane 持有的 4 个 C/D 元素坐标 (m, n)。"""
    # 和 A 的 a0/a1 同一套行规律：这就是 FlashAttention 能把 S = QK^T 的结果（C 布局）
    # 直接当成下一次 P·V 的 A 操作数（A 布局）的原因——行完全对得上，只差 dtype 转换。
    g, t = lane // 4, lane % 4
    return [(g, 2 * t), (g, 2 * t + 1), (g + 8, 2 * t), (g + 8, 2 * t + 1)]


def mma_m16n8k16(a: np.ndarray, b: np.ndarray, c: np.ndarray) -> np.ndarray:
    """warp 级 MMA：按布局拼出 A、B、C，算 D = A@B + C，再按 C 布局分回各 lane。"""
    A = np.zeros((16, 16))
    B = np.zeros((16, 8))
    C = np.zeros((16, 8))
    for lane in range(32):
        for v, (r, k) in zip(a[lane], a_coords(lane)):
            A[r, k] = v
        for v, (k, n) in zip(b[lane], b_coords(lane)):
            B[k, n] = v
        for v, (r, n) in zip(c[lane], c_coords(lane)):
            C[r, n] = v
    D = A @ B + C
    d = np.zeros((32, 4))
    for lane in range(32):
        d[lane] = [D[r, n] for r, n in c_coords(lane)]
    return d


def ldmatrix(smem: np.ndarray, row_addrs, num: int) -> np.ndarray:
    """模拟 ldmatrix.x{num}：lane 8j..8j+7 给出矩阵 j 的 8 行地址；结果 (32, 2·num)。"""
    if num not in (1, 2, 4):
        raise ValueError("ldmatrix num must be 1, 2 or 4")
    # 关键点：“谁提供地址”和“谁拿到数据”是两回事。地址按 lane 8j+r 给出矩阵 j 的第 r 行，
    # 数据则按 mma 的 fragment 规律分发：lane l 拿到每个矩阵第 l//4 行的第 2(l%4)、2(l%4)+1 列。
    # 硬件在 warp 内部做这次“转置式”重分发，所以一条指令代替了 8 次 32-bit 的 ld.shared + shuffle。
    out = np.zeros((32, 2 * num), dtype=smem.dtype)
    for j in range(num):
        rows = [smem[row_addrs[8 * j + r]: row_addrs[8 * j + r] + 8] for r in range(8)]
        for lane in range(32):
            r, c = lane // 4, 2 * (lane % 4)
            out[lane, 2 * j] = rows[r][c]
            out[lane, 2 * j + 1] = rows[r][c + 1]
    return out


def a_tile_row_addrs(base: int, ld: int) -> list[int]:
    """ldmatrix.x4 读 16×16 A tile 时每个 lane 提供的行地址。"""
    # 寄存器 a0..a3 依次是：左上、左下、右上、右下 四个 8×8 子矩阵。
    # 矩阵 j = lane // 8：j 的低位选上下（+8 行），高位选左右（+8 列）。
    addrs = []
    for lane in range(32):
        j, r = lane // 8, lane % 8
        row = r + 8 * (j % 2)
        col = 8 * (j // 2)
        addrs.append(base + row * ld + col)
    return addrs


def b_tile_row_addrs(base: int, ld: int) -> list[int]:
    """ldmatrix.x2 读 16(K)×8(N) 的 B tile（B^T 按 N×K 存）时每个 lane 提供的行地址。"""
    # 每一行是一个 n、8 个连续 k。矩阵 0 = k 0..7，矩阵 1 = k 8..15。
    # 若 B 是 K×N 存放（n 连续），就得用 ldmatrix.trans，或者改用 TN 布局——
    # 这就是 CUTLASS 里 “TN GEMM” 最常见、最快的原因。
    addrs = []
    for lane in range(32):
        if lane < 16:
            j, r = lane // 8, lane % 8
            addrs.append(base + r * ld + 8 * j)
        else:
            addrs.append(base)
    return addrs

面试官追问 & 对照源码

  • “Hopper 的 wgmma 还需要 ldmatrix 吗？” 不需要：A、B 用 64-bit SMEM 描述符直接从 SMEM 读（desc_a / desc_b），只有累加器在寄存器里。描述符里要写 swizzle 模式，所以 A3 / B3 的 swizzle 必须和 TMA 写入一致。
  • “Blackwell 呢？” tcgen05.mma 由一个线程发起，A/B 在 SMEM（A 也可以在 TMEM），D 在 TMEM：fragment 布局这件事从寄存器搬到了 TMEM 的 lane/列上（C1）。
  • “m16n8k16 的 FP8 版本？” sm89 / sm120 有 mma.sync … .e4m3，k = 32：同样的 16×8 输出，每个寄存器装 4 个 FP8。sm120 的 block-scaled 版本见 SM120_16x8x32_TN。
  • “为什么叫 TN？” BLAS 的列主序视角下 A 转置（T）、B 不转置（N）；换成行主序就是 “A 是 M×K 行主序、B 是 N×K 行主序”，两边都是 K 连续——ldmatrix 非转置就能直接读，所以 TN 是最快的布局。
