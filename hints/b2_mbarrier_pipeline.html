B2 · mbarrier：相位位、事务字节与 TMA 生产者/消费者环

Hopper 之后，kernel 里一切异步协作（TMA 写完了没有、MMA 读完了没有）都靠 SMEM 里的 mbarrier：到达计数 + 事务字节 + 一个相位位。理解了相位位怎么翻、等待方的 parity 怎么跟着翻，就读得懂 CUTLASS 的整个 pipeline 层。

题面速览

  • 在系统中的位置：PTX 包装在 ClusterTransactionBarrier（arrive_and_expect_tx、wait(phase) 自旋在 mbarrier.try_wait.parity 上）；环形缓冲在 PipelineTmaAsync，位置是 PipelineState，producer 从 make_producer_start_state（phase = 1）开始。Blackwell 的 PipelineUmmaAsync 是同一套东西。
  • 你要实现：MBarrier、PipelineState、make_producer_start_state、TmaPipeline（每个 stage 一对 full / empty barrier）。
  • 难点在这几条规则：
    1. 相位完成 = pending arrive 归零且 tx 字节归零；完成时硬件自己把计数装回初值、翻转相位位。
    2. try_wait(parity) ⇔ parity != phase：等的是“parity 指的那个相位已经完成”。
    3. producer 先 arrive_and_expect_tx（先记字节再到达），否则相位会在一个字节都没写时完成。
    4. PipelineState 每绕一圈翻转 phase；producer 从 phase 1 开始，所以第一圈不等。

验收要点：到齐才翻相位 · 自动重置 · 字节挡住相位 · complete_tx 可以先到 · 先 arrive 后 expect 会提前完成（反例）· state 绕圈翻转 · producer 第一圈不等、第二圈要等 · 失败的 acquire 不改状态 · 随机交错下 1–5 级、1–3 个 consumer 都按顺序收到每一块且从不读到被覆盖的数据。

直觉与类比

类比 · 只有一位的“第几轮”灯

每个 stage 门口有两盏灯：“满”（full）和“空”（empty）。每盏灯只有一个比特：亮 / 灭，每完成一轮就切换一次。等的人手里拿着一张卡片写着“我在等 parity = p 的那一轮完成”，看到灯的状态不等于 p 就进门（p != phase）。因为只有一位，等的人最多只能落后一轮——ring buffer 正好保证这一点：producer 不可能比 consumer 快两圈，因为它要等“空”灯。“满”灯的完成条件比较特别：producer 到了（1 次 arrive）而且快递员（TMA）报告的字节数和预约的一样多。producer 必须先预约字节再打卡，不然打卡的瞬间灯就切换了，consumer 冲进去拿到的是空箱子。

逐步演示

▶ 2 级、1 个 consumer、每块 64 字节
1. 第一圈不用等

producer 状态 (0, 1)：empty[0].try_wait(1)，empty 的 phase 是 0 ≠ 1 → 真。对 full[0] 登记 64 字节并到达：pending = 0，但 tx = 64，相位不翻。同样拿到 slot 1。

2. 第二圈要等

producer 状态 (0, 0)：empty[0].try_wait(0)，phase 仍是 0 → 假，producer_try_acquire 返回 False，什么都不改。

3. 字节一半一半到

consumer 状态 (0, 0)：full[0].try_wait(0) → 假。TMA 写了 32 字节：tx = 32，还是假。又写了 32：tx = 0 且 pending = 0 → full[0] 翻到 phase 1，consumer 的 try_wait(0) 变真。

4. 释放

consumer 读完、consumer_release：empty[0] 的 1 次到达凑齐 → phase 1。producer 的 try_wait(0) 终于为真，拿到 slot 0 开始第二圈。consumer 前进到 (1, 0)，绕回 slot 0 时会变成 (0, 1)。

易错点

  • parity 判断写反。 写成 parity == phase 会让 producer 第一圈就卡死、consumer 读到空数据；随机交错测试会报 deadlock 或 “stale data”。
  • 相位完成后不重置计数。 第二圈 pending 已经是 0，一次 arrive 就变成 −1，永远完成不了（test_barrier_resets_itself_for_next_phase）。
  • producer 先 arrive 后 expect。 test_arrive_before_expect_would_complete_early 演示了这个反例：相位会立刻完成。
  • acquire 失败时也登记了字节。 下次成功时又登记一次，full 永远等不到双倍的字节（test_failed_acquire_changes_nothing）。
  • producer 从 phase 0 开始。 第一圈就等 empty，而 empty 还没有人 arrive 过：死锁。

关键问题

  1. 为什么一位相位就够了？什么情况下不够？
  2. consumer 的初始 phase 为什么是 0、producer 的为什么是 1？
  3. 如果有 2 个 consumer warpgroup，empty barrier 的到达数应该是多少？
  4. TMA 拷贝的是越界的尾 tile，expect_tx 写多少？
L2思路与常见坑拆解与常见坑（中度剧透）
  • MBarrier 状态：expected, _pending, _tx, phase, completed。所有会改计数的方法最后都调用一个 _maybe_complete()：pending == 0 and tx == 0 时翻转、计数、重置。
  • expect_tx 只加字节、不检查完成（此时 pending 一般还没到 0）。
  • PipelineState.advance：index += 1，等于 stages 时归零并 phase ^= 1。
  • TmaPipeline.producer_try_acquire：先 empty[i].try_wait(state.phase)，失败直接返回 False；成功才 full[i].arrive_and_expect_tx(tx_bytes)。
L3详解：答案几乎是答案（重度剧透）
关键问题答案
  1. 等待方只需要区分“我等的这一轮完成了没有”和“还在上一轮”。只要等待方永远不落后两轮就够；ring buffer 里 producer 要先等 empty、consumer 要先等 full，两边互相牵制，差距不会超过一圈。
  2. consumer 第一圈要等 full 的第 0 个相位完成：parity 0。producer 第一圈不应该等（缓冲本来就空），用 parity 1 指向“上一个相位”，初始状态下它算已完成。
  3. 2（或者 2 × 每个 warpgroup 里实际调用 arrive 的线程数，CUTLASS 里是每个 warpgroup 一个 elected 线程，所以 num_consumers = warpgroup 数）。见 wgmma_tma_sm90.cu 里 ConsumerBarType::init(&consumer_mbar[pipe], 128)——那个教程里是每个线程都 arrive，所以是 128。
  4. 整个 box 的字节数，越界填零的部分也算（B3 的 tx_bytes）。

"""B2 · mbarrier: phase parity, transaction bytes and the TMA producer/consumer ring — reference solution.

Hopper 起，SMEM 里的 `mbarrier` 是 kernel 内部一切异步协作的“信号灯”：TMA 拷贝完成时按字节数
给它记账（complete_tx），MMA warp 等它翻相位才开始读；读完再 arrive 另一个 mbarrier 通知 producer
这块 SMEM 可以覆盖了。CUTLASS 的 `PipelineTmaAsync` 用每个 stage 一对 barrier（full / empty）
加一个 `PipelineState(index, phase)` 把这一切串成环形缓冲。这道题从零实现这三样东西。

MBarrier(expected_arrivals)：
- 内部状态：本相位还差几次 arrive（pending，初值 expected_arrivals）、还差多少事务字节（tx，初值 0）、
  当前相位位 phase（初值 0）。
- arrive(count=1)：pending −= count。
- expect_tx(nbytes)：tx += nbytes。
- arrive_and_expect_tx(nbytes)：先 expect_tx 再 arrive(1)。
- complete_tx(nbytes)：tx −= nbytes（允许暂时为负：TMA 的完成可能早于 expect 被看到）。
- 每次 arrive / complete_tx 之后，若 pending == 0 且 tx == 0，本相位完成：phase ^= 1，
  pending 重置为 expected_arrivals，tx 重置为 0，completed 计数 +1。
- try_wait(parity) -> bool：parity 指的那个相位是否已经完成，等价于 `parity != phase`
  （PTX `mbarrier.try_wait.parity` 的语义：初始 phase=0 时等 parity 1 立即返回真）。
- 属性 phase、completed（已完成的相位数）。

PipelineState(stages, index=0, phase=0)：advance() 使 index += 1，到 stages 时回到 0 并翻转 phase。
make_producer_start_state(stages)：返回 index 0、phase 1 的状态（缓冲一开始就是空的，producer 不必等）。

TmaPipeline(stages, num_consumers, tx_bytes)：每个 stage 一个 full = MBarrier(1)、
一个 empty = MBarrier(num_consumers)。
- producer_try_acquire(state) -> bool：empty[state.index].try_wait(state.phase) 为真时，
  对 full[state.index] 调用 arrive_and_expect_tx(tx_bytes) 并返回 True；否则什么都不做，返回 False。
- tma_complete(stage, nbytes)：模拟 TMA 引擎写完 nbytes：full[stage].complete_tx(nbytes)。
- consumer_try_wait(state) -> bool：full[state.index].try_wait(state.phase)。
- consumer_release(state)：empty[state.index].arrive()。
- 属性 full、empty（MBarrier 列表）。

API
    MBarrier(expected_arrivals)  .arrive(count=1) .expect_tx(n) .arrive_and_expect_tx(n) .complete_tx(n)
                                 .try_wait(parity) -> bool  .phase  .completed
    PipelineState(stages, index=0, phase=0)  .advance()  .index  .phase
    make_producer_start_state(stages) -> PipelineState
    TmaPipeline(stages, num_consumers, tx_bytes)  .producer_try_acquire(state) -> bool
                 .tma_complete(stage, n)  .consumer_try_wait(state) -> bool  .consumer_release(state)
"""
from __future__ import annotations


class MBarrier:
    def __init__(self, expected_arrivals: int):
        """expected_arrivals 次 arrive + 事务字节清零 = 一个相位完成。"""
        # 硬件里就是 SMEM 里的一个 64-bit 字：pending 计数、tx 计数和相位位挤在一起。
        # 线程们等的不是“值”，而是“相位位翻了没有”——所以同一个 barrier 可以被反复使用，
        # 不需要任何人去重置它：完成的瞬间硬件自己把计数装回初值。
        self.expected = expected_arrivals
        self._pending = expected_arrivals
        self._tx = 0
        self.phase = 0
        self.completed = 0

    def _maybe_complete(self) -> None:
        if self._pending == 0 and self._tx == 0:
            self.phase ^= 1
            self.completed += 1
            self._pending = self.expected
            self._tx = 0

    def arrive(self, count: int = 1) -> None:
        """到达 count 次。"""
        self._pending -= count
        self._maybe_complete()

    def expect_tx(self, nbytes: int) -> None:
        """声明本相位还要等 nbytes 个事务字节。"""
        # expect_tx 本身不检查完成：pending 还没到 0 时完成不了；
        # 若 complete_tx 已经先到（tx 为负），这次 expect 把它拉回 0，下一次 arrive 就完成。
        self._tx += nbytes

    def arrive_and_expect_tx(self, nbytes: int) -> None:
        """producer 的标准动作：先登记字节，再到达。"""
        # 顺序很重要：如果先 arrive，pending 变 0 而 tx 还是 0，相位会在 TMA 一个字节都没写的时候就完成，
        # consumer 读到的是旧数据。PTX 的 mbarrier.arrive.expect_tx 把两步做成一条原子指令。
        self._tx += nbytes
        self.arrive(1)

    def complete_tx(self, nbytes: int) -> None:
        """TMA（或 bulk copy）写完 nbytes 时由硬件调用。"""
        self._tx -= nbytes
        self._maybe_complete()

    def try_wait(self, parity: int) -> bool:
        """parity 对应的相位是否已经完成。"""
        # 只有一位相位，所以只能区分“当前相位”和“上一个相位”。
        # 这就要求等待方永远不能落后两圈——ring buffer 的 empty/full 配对天然保证了这一点。
        return parity != self.phase


class PipelineState:
    def __init__(self, stages: int, index: int = 0, phase: int = 0):
        """ring buffer 上的位置：第几个 stage，以及这是第几圈（只记奇偶）。"""
        self.stages = stages
        self.index = index
        self.phase = phase

    def advance(self) -> None:
        """前进一格；绕回 0 时翻转 phase。"""
        # 每绕一圈，同一个 stage 的 barrier 恰好完成一个相位，所以我们等的 parity 也要翻转。
        self.index += 1
        if self.index == self.stages:
            self.index = 0
            self.phase ^= 1


def make_producer_start_state(stages: int) -> PipelineState:
    """producer 从 phase 1 开始：empty barrier 的“上一个相位”视为已完成，所以第一圈不用等。"""
    return PipelineState(stages, 0, 1)


class TmaPipeline:
    def __init__(self, stages: int, num_consumers: int, tx_bytes: int):
        """每个 stage 一对 barrier：full（1 次 arrive + tx 字节）和 empty（num_consumers 次 arrive）。"""
        self.stages = stages
        self.tx_bytes = tx_bytes
        self.full = [MBarrier(1) for _ in range(stages)]
        self.empty = [MBarrier(num_consumers) for _ in range(stages)]

    def producer_try_acquire(self, state: PipelineState) -> bool:
        """等 empty；拿到后对 full 登记 tx_bytes 并到达。"""
        if not self.empty[state.index].try_wait(state.phase):
            return False
        # 拿到 slot 之后、发 TMA 之前登记字节数：full 的完成条件变成“producer 到了 + 字节全到”。
        self.full[state.index].arrive_and_expect_tx(self.tx_bytes)
        return True

    def tma_complete(self, stage: int, nbytes: int) -> None:
        """TMA 引擎写完一段。"""
        self.full[stage].complete_tx(nbytes)

    def consumer_try_wait(self, state: PipelineState) -> bool:
        """数据到齐了吗？"""
        return self.full[state.index].try_wait(state.phase)

    def consumer_release(self, state: PipelineState) -> None:
        """这个 consumer 读完了这个 slot。"""
        # 所有 consumer 都 release 之后 empty 才翻相位，producer 才能覆盖。
        # Hopper 的 wgmma 是异步的：release 必须放在 warpgroup_wait 之后，
        # 否则 Tensor Core 可能还在读这块 SMEM（CUTLASS 的 mma 里 release 的是“上一块”）。
        self.empty[state.index].arrive()

面试官追问 & 对照源码

  • “try_wait 和 test_wait 有什么区别？” test_wait 立即返回；try_wait 可以在硬件里挂起一段时间（带超时提示），避免纯自旋占发射槽。CUTLASS 的 ClusterBarrier::wait 就是 try_wait 的循环。
  • “cluster 里别的 CTA 能 arrive 我的 barrier 吗？” 能：mbarrier.arrive.shared::cluster 带目标 CTA id。multicast TMA 写进多个 CTA 时，每个目标 CTA 自己的 full barrier 各收到自己那份字节；而 empty barrier 要收集所有用到这块数据的 CTA 的 release（consumer_release 里的 dst_blockid_）。
  • “wgmma 是异步的，consumer 什么时候能 release？” 必须在 warpgroup_wait<N> 确认读这块 SMEM 的 wgmma 都完成之后；CUTLASS 的 mainloop 里 release 的是“上一块”，让一个 wgmma 批次保持在飞行中。
  • “Blackwell 上谁来 arrive empty？” MMA 是一个线程发起的异步 tcgen05.mma，用 tcgen05.commit 让硬件在 MMA 读完后 arrive 指定的 mbarrier：umma_arrive。
