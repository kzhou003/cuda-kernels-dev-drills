D3 · FA4 的 softmax：FMA 上的 exp2 多项式与条件 rescale

Tensor Core 每代翻倍，算 exp 的单元（MUFU）却没变：到 B200 上，一次 exp 的时间已经和 128 维的 MMA 一样长。FA4 的回答有两个：把一部分 exp2 挪到 FMA 单元上用多项式算；行最大值只涨一点时干脆不 rescale。

题面速览

  • 在系统中的位置：FA4（CuTe DSL）的 ex2_emulation（fmax(x, −127)、用 add.rm 取 floor、POLY_EX2 的 3 次多项式、整数加法拼进指数位）；条件 rescale 在 Softmax.update_row_max（rescale_threshold，MLA 内核默认 8.0）；哪些 fragment 用模拟由 config.py 的 ex2_emu_freq / ex2_emu_start_frg 决定。真跑需要 B200（sm100a）；这两个技巧本身在任何 GPU 上都成立，可以作为 G3 的扩展练习移植到 5090 上。
  • 你要实现：ex2_emulation、softmax_attention_cond_rescale、exp_to_mma_ratio、balanced_emulation_fraction。
  • 难点在这几条规则：
    1. 2^x = 2^⌊x⌋ · 2^f，f ∈ [0, 1)：负数要用 floor（−0.5 = −1 + 0.5），不是截断。
    2. 2^⌊x⌋ 不用乘法：把 j 左移 23 位加到 p 的 IEEE 位模式上（指数位 +j）；x 先夹到 ≥ −127。
    3. 条件 rescale：log2 域里最大值的增量 ≤ threshold 时保持旧的 m，P 的值最多到 2^threshold；最后 acc / l 用的是同一个 m，结果仍然精确。
    4. 每对 (q, k)：MMA 4d FLOP、exp 1 次；比值 = (1/mufu) / (4d/tc)。

验收要点：整数点上精确 · 最大相对误差 < 2e−4 且确实是近似 · 负的小数用 floor · 极小输入夹住 · 三种 threshold 都精确 · threshold 越大 rescale 越少 · 大跳变仍然 rescale 且按行计数 · threshold = 0 时每次涨都 rescale · A100 / H100 / B200 的比值 0.25 / 0.5 / 1 · 平衡比例。

直觉与类比

类比 · 只有一台计算器的会计

每算一个注意力分数，会计要做 4·d 次乘加（交给一排算盘 = Tensor Core）和 1 次查指数表（交给唯一一台计算器 = MUFU）。算盘每代翻倍，计算器还是那一台，到 B200 上两边一样慢。办法一：让一部分指数用算盘按公式算（3 次乘加的多项式 + 改一下指数位），两边都不闲着。办法二：换汇率（rescale）本来是“基准变了就把账本全部重抄一遍”，现在改成“基准只涨了一点点就不换”，反正最后除法时分子分母用的是同一个基准，账一样平。

逐步演示

▶ 每一代：exp 和 MMA 谁慢（d = 128，MUFU 16 次/时钟/SM）
1. A100

Tensor Core 2048 FLOP/时钟/SM：每对 (q,k) 的 MMA 要 4·128 / 2048 = 0.25 时钟，exp 要 1/16 = 0.0625：比值 0.25（exp_to_mma_ratio(2048, 16, 128)）。softmax 不是瓶颈，FA2 不用管它。

2. H100

4096：比值 0.5。softmax 占 MMA 时间一半，FA3 用两个 warpgroup 的 pingpong 把 softmax 藏在另一个 warpgroup 的 GEMM 后面（B4）。

3. B200

8192：比值 1.0。就算完美重叠，MUFU 也和 Tensor Core 一样忙。

4. FA4

把比例 f 的 exp 挪到 FMA（每 SM 128 次/时钟，一次模拟约 6 条指令）：两边相等时 f = 128 / (128 + 6·16) = 0.57（balanced_emulation_fraction(16, 128, 6)）。3 次多项式的最大相对误差 8.8e−5（在 [−30, 10] 上测得），远小于 BF16 的 2⁻⁹ ≈ 2e−3。真实 kernel 的 FMA 还要做别的事，所以 FA4 实际挪过去的比例更小。

条件 rescale 的效果（8 个 query、512 个 key、块 32，由参考解算出）：threshold = 0、1、2、4、8 时，逐行 rescale 次数分别是 17、11、7、3、0，输出完全一致。

易错点

  • 用截断代替 floor。 int(−0.5) = 0，小数部分变成 −0.5，多项式在 [0, 1) 外误差很大（test_ex2_negative_fraction_uses_floor）。
  • 指数位加法溢出。 x = −1000 时 j << 23 会把符号位也改掉；先 max(x, −127)。
  • 在 float64 里算多项式。 题面要求全程 float32，结果 dtype 也要是 float32。
  • 条件 rescale 时更新了 m 却没乘 acc。 “不 rescale” 意味着 m、acc、l 三个都不动；只改一部分结果就错了。
  • threshold = 0 时把 delta == 0 也算一次 rescale。 最大值没变不需要 rescale，也不计数。

关键问题

  1. 为什么 2^⌊x⌋ 可以用一次整数加法实现？
  2. softmax 里的 x 几乎总是 ≤ 0，fmax(x, −127) 会不会影响结果？
  3. 不 rescale 时 P 最大会到多少？为什么 FP32 不会溢出？
  4. 为什么条件 rescale 不改变最终结果？
L2思路与常见坑拆解与常见坑（中度剧透）
  • ex2_emulation：x = maximum(asarray(x, float32), -127)；j = floor(x)；f = x - j；Horner：((c3*f + c2)*f + c1)*f + c0；(p.view(int32) + (j.astype(int32) << 23)).view(float32)。标量输入返回标量。
  • 条件 rescale：log2 域 s = scale·LOG2E·Q Kᵀ；第一块直接设 m；之后 delta = m - cand，keep = delta >= -threshold（threshold > 0）或 delta == 0；factor = where(keep, 1, exp2(delta))；更新 acc、l、m；再加本块。
L3详解：答案几乎是答案（重度剧透）
关键问题答案
  1. FP32 = 符号 · 2^(指数 − 127) · 1.尾数。p ∈ [1, 2) 的指数字段是 127；把 j 加到指数字段（位 23–30）上，就是乘 2^j。整数加法在 ALU / FMA 管线上做，不碰 MUFU。
  2. 2⁻¹²⁷ 已经小于 FP32 最小正规数，再小对 softmax 的和没有任何影响（被 BF16 的 P 舍成 0）。
  3. 新分数比 m 最多高 threshold（log2 域），所以 P ≤ 2^threshold = 256（threshold = 8）。l 是 P 的和，序列长 128K 也只到 2^25 量级，FP32 足够。
  4. O = Σ 2^(s_j − m) v_j / Σ 2^(s_j − m)：分子分母同一个 m，2^(−m) 约掉。m 只要保证不溢出就行，不必是真正的最大值。

"""D3 · FA4 softmax tricks on Blackwell: exp2 on the FMA pipe and conditional rescaling — reference solution.

每个 (query, key) 对要做 4·d 次 MMA FLOP 和 1 次 exp。Tensor Core 每代翻倍，算 exp 的 MUFU
（每 SM 每时钟 16 次）却没变：A100 上 exp 的时间约是 MMA 的 1/4，H100 约 1/2，B200 上已经一样长。
FA4 的两个招：
1. 一部分 exp2 不用 MUFU，而是在 FMA 单元上用多项式算：2^x = 2^⌊x⌋ · 2^f，f ∈ [0, 1)，
   2^f 用 3 次多项式（Horner，3 次 FMA），2^⌊x⌋ 直接加到浮点数的指数位上。BF16 的 P 只有 8 位尾数，
   3 次多项式的误差（~1e-4）已经足够。
2. 条件 rescale：行最大值只涨了一点（log2 域里 ≤ threshold，比如 8）时，不更新 m、不 rescale O，
   让 P 的值最大到 2^threshold（FP32 装得下）。最终 O = acc / l 用的是同一个 m，结果仍然精确。
   省掉的是每块对整个 O 累加器（在 TMEM 里）的一次读改写。

给定（given）：POLY_EX2（FA4 源码里 degree 3 的系数，[c0, c1, c2, c3]）、LOG2E。

- ex2_emulation(x)：float32 输入（标量或数组），返回 float32 的 2^x 近似。步骤：x = max(x, −127)；
  j = floor(x)；f = x − j；p = ((c3·f + c2)·f + c1)·f + c0（全部 float32）；
  结果 = 把 p 的 IEEE 位模式（int32）加上 j << 23 后按 float32 解释。假设 x ≤ 127。
- softmax_attention_cond_rescale(Q, K, V, scale, Bc, threshold) -> (O, n_rescales)：
  log2 域的 online softmax：s = scale·LOG2E·QKᵀ。对每个 key 块，每一行：
    m_cand = max(m, rowmax(s_blk))；第一块：m = m_cand，不算 rescale；
    之后：delta = m − m_cand（≤ 0）。threshold > 0 且 delta ≥ −threshold 时保持 m 不变、不 rescale；
    否则 acc、l 乘 2^delta，m = m_cand，n_rescales += 1（逐行计数）。
    然后 p = 2^(s_blk − m)，l += Σp，acc += p·V_blk。
  最后 O = acc / l。用 float64 计算（np.exp2）。threshold = 0 表示每次最大值变大都 rescale
  （delta < 0 时；delta == 0 时 2^0 = 1，不计数）。
- exp_to_mma_ratio(tc_flops_per_clk, mufu_per_clk, d)：每对 (q, k) 的 exp 时间 / MMA 时间
  = (1 / mufu_per_clk) / (4·d / tc_flops_per_clk)。
- balanced_emulation_fraction(mufu_per_clk, fma_per_clk, ops_per_emulated)：把比例 f 的 exp 挪到 FMA 上，
  使 MUFU 时间 (1−f)/mufu 与 FMA 时间 f·ops/fma 相等时的 f = fma / (fma + ops·mufu)。

API
    POLY_EX2, LOG2E                                    given
    ex2_emulation(x) -> np.ndarray | np.float32
    softmax_attention_cond_rescale(Q, K, V, scale, Bc, threshold) -> tuple[np.ndarray, int]
    exp_to_mma_ratio(tc_flops_per_clk, mufu_per_clk, d) -> float
    balanced_emulation_fraction(mufu_per_clk, fma_per_clk, ops_per_emulated) -> float
"""
from __future__ import annotations

import numpy as np

POLY_EX2 = (1.0, 0.695146143436431884765625, 0.227564394474029541015625, 0.077119089663028717041015625)
LOG2E = 1.4426950408889634


def ex2_emulation(x):
    """FA4 的 ex2_emulation：整数部分进指数位，小数部分用 3 次多项式。"""
    x = np.maximum(np.asarray(x, dtype=np.float32), np.float32(-127.0))
    # FA4 里 floor 是用 “加 1.5·2^23、向下舍入” 的技巧在 FMA 管线上做的（add.rm），
    # 这样整数部分直接落在尾数低 8 位里，后面用一次整数加法拼进指数位。这里用 np.floor 表达同一件事。
    j = np.floor(x)
    f = (x - j).astype(np.float32)
    c0, c1, c2, c3 = (np.float32(c) for c in POLY_EX2)
    p = ((c3 * f + c2) * f + c1) * f + c0          # 3 次 FMA，p ∈ [1, 2)
    # p 的指数是 0（偏置 127）；加上 j << 23 就是把指数改成 j，即乘 2^j。
    # x ≥ −127 保证结果不会下溢成负的指数位（FA4 同样先 fmax(x, -127)）。
    bits = p.view(np.int32) + (j.astype(np.int32) << 23)
    out = bits.view(np.float32)
    return out if out.ndim else np.float32(out)


def softmax_attention_cond_rescale(Q, K, V, scale: float, Bc: int, threshold: float):
    """log2 域 online softmax；最大值只涨一点时跳过 rescale。"""
    Q, K, V = (np.asarray(a, dtype=np.float64) for a in (Q, K, V))
    nq, nk = Q.shape[0], K.shape[0]
    m = np.full(nq, -np.inf)
    l = np.zeros(nq)
    acc = np.zeros((nq, V.shape[1]))
    n_rescales = 0
    for j0 in range(0, nk, Bc):
        s = scale * LOG2E * (Q @ K[j0:j0 + Bc].T)
        cand = np.maximum(m, s.max(axis=1))
        if j0 == 0:
            m = cand
        else:
            delta = m - cand
            keep = (delta >= -threshold) if threshold > 0 else (delta == 0)
            # keep 的行：继续用旧的 m。新块里的 s 可能比 m 大，最多大 threshold，
            # 所以 p = 2^(s − m) ≤ 2^threshold（threshold = 8 → 256），FP32 的 acc、l 毫无压力。
            # 只要分子 acc 和分母 l 用的是同一个 m，最后相除时 2^m 抵消，结果精确。
            factor = np.where(keep, 1.0, np.exp2(delta))
            n_rescales += int((~keep).sum())
            acc *= factor[:, None]
            l *= factor
            m = np.where(keep, m, cand)
        p = np.exp2(s - m[:, None])
        l += p.sum(axis=1)
        acc += p @ V[j0:j0 + Bc]
    # FA4 里 rescale 由单独的 “correction” warpgroup 做（O 在 TMEM 里，要 tcgen05.ld / st 一遍），
    # 所以少一次 rescale 就是少一次对 TMEM 里整个 O tile 的读改写。
    return acc / l[:, None], n_rescales


def exp_to_mma_ratio(tc_flops_per_clk: float, mufu_per_clk: float, d: int) -> float:
    """每对 (q, k)：exp 时间 / MMA 时间。"""
    # 每对 (q,k)：S 的一个元素要 2d FLOP（QKᵀ），P·V 再 2d FLOP，共 4d；exp 一次。
    return (1.0 / mufu_per_clk) / (4.0 * d / tc_flops_per_clk)


def balanced_emulation_fraction(mufu_per_clk: float, fma_per_clk: float, ops_per_emulated: float) -> float:
    """MUFU 和 FMA 两条管线时间相等时，挪到 FMA 上的 exp 比例。"""
    # 真实 kernel 里 FMA 管线还要做 scale、max、类型转换等，所以 FA4 实际挪过去的比例更小，
    # 而且按 fragment 交错（config.py 里的 ex2_emu_freq / ex2_emu_start_frg）。
    return fma_per_clk / (fma_per_clk + ops_per_emulated * mufu_per_clk)

面试官追问 & 对照源码

  • “为什么 FA4 不全部用多项式？” FMA 管线也要做缩放、取最大值、类型转换；全部挪过去 FMA 就成了瓶颈。最优是让两条管线一样忙（balanced_emulation_fraction），实际由 ex2_emu_freq 按 fragment 交错。
  • “rescale_threshold 为什么是 8？” log2 域的 8 = 256 倍：BF16 的 P 最大 256 不会损失精度（指数范围很大），FP32 的 l 和 O 也安全。更大的阈值收益很小。
  • “FA4 的 O 在 TMEM 里，rescale 怎么做？” 专门的 correction warpgroup 用 tcgen05.ld 读 O、乘因子、tcgen05.st 写回；它和 MMA、softmax warp 通过 mbarrier 握手。条件 rescale 让它大多数时候什么都不用做。
  • “这两个技巧能用在 5090 上吗？” 能：5090 的 Tensor Core 不快，exp 本来不是瓶颈（A1 的比值约 0.06 量级），收益很小；但条件 rescale 能省寄存器里的乘法，作为 G3 的扩展练习是个好起点。
